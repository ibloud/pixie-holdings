## Demo emphasis

Lead with the product loop:

**ASK → INSPECT → PREVIEW → EXPLAIN → APPROVE → OPTIONAL RECEIPT**

Then show:

1. six consequence ledgers;
2. accessibility behavior;
3. MCP tool discovery/call;
4. provenance/public-receipt preview;
5. open repository + contributor invitation.

Do not spend the demo explaining the entire Loptr Lab universe. The hackathon entry should prove one working idea and use that proof to invite people into the larger ecosystem.

## Contributor CTA

The repository should make one thing obvious after the demo:

**Run it. Test it. Tell us what breaks.**

The first contributor targets are accessibility, MCP/Alexa+ interoperability, documentation, provenance, and ecosystem mapping.
